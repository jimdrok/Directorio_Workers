SUPABASE + CLOUDFLARE

Una base clara
para un producto real.

Supabase administra autenticación, datos, archivos y reglas de negocio. Cloudflare despliega la interfaz React. Esta vista explica cómo se conectan.

Propuesta para la siguiente etapa. El MVP actual aún usa los backends anteriores. Esta documentación no conecta una cuenta Supabase ni modifica datos reales.
01 · INTERFAZ

React en Cloudflare

Inicio, búsqueda, ficha pública, login, panel y administración. Navegación, formularios y estados en español.

→
02 · BACKEND

Supabase

Auth identifica. PostgreSQL y RLS autorizan. RPC guarda en transacciones. Edge Functions gestionan archivos privados.

→
03 · CONTACTO

WhatsApp

Contacto directo con el trabajador. Mensaje predefinido según su oficio, sin chat ni reservas internas.

No duplicar sesiones ni perfiles en Cloudflare. El frontend usa la clave pública de Supabase; las claves privilegiadas permanecen en el backend.

MODELO RELACIONAL

Cómo se relacionan

Un usuario tiene un perfil. Un perfil tiene un oficio, una ubicación y muchas parroquias de cobertura. Fotos y testimonios pertenecen al perfil; moderación puede ocultarlo sin editar sus servicios.

RESPONSABILIDADES

Los módulos del producto

Identidad

Registro, confirmación, login, sesión y recuperación con Supabase Auth. El rol administrativo se asigna en backend, nunca en un formulario.

Catálogos

Oficios y parroquias. Categorías desactivables sin eliminar referencias. Dos catálogos de UUID compartidos por búsqueda y edición.

Directorio

Inicio, resultados y perfil público. Búsqueda por oficio y parroquia de cobertura, paginación y mensajes vacíos/indisponibles.

Mi perfil

Datos públicos, servicios, años de experiencia y cobertura. Borrador, publicación y pausa; RPC guarda perfil e hijos en una transacción.

Portafolio

Un avatar y hasta seis fotos. Storage privado, validación real de archivo y asociación por slots. Eliminar archivos huérfanos tras fallos.

Testimonios

Nombre público y texto del recomendante. Etiqueta fija: “Testimonio aportado por el trabajador”. Sin estrellas ni reseñas verificadas.

Contacto

WhatsApp con teléfono E.164 y mensaje codificado. No almacenar conversaciones, citas o pagos.

Administración

Ocultar/restaurar perfiles, gestionar categorías y consultar auditoría. No editar libremente los servicios de otros trabajadores.

Infraestructura

Cliente Supabase único, contratos TypeScript, errores traducidos, migraciones y pruebas RLS. Cloudflare solo distribuye la interfaz.

RECORRIDOS

Del registro al contacto

    Regla de visibilidad

    Este explorador es una simulación documental: no ejecuta consultas ni cambia Supabase.

    visible = status === 'published' && !is_hidden

    Publicado requiere campos obligatorios y al menos una parroquia de cobertura. Republicar no elimina el ocultamiento administrativo.

    RLS + grants + RPC. Las lecturas respetan visibilidad y propiedad. Las escrituras de la propuesta SQL están cerradas hasta implementar RPC autorizadas y transaccionales.

    Fotografías privadas

    Bucket worker-media, hasta 2 MB por imagen JPEG/PNG/WebP. Una Edge Function revisa visibilidad o propiedad antes de entregar archivos. Un bucket público seguiría exponiendo fotos al pausar.

    Las URLs firmadas tienen una ventana hasta su expiración. Para revocación estricta de nuevas solicitudes, servir medios a través de una función con comprobación actual y sin caché. Los archivos ya descargados no pueden retirarse.

    Datos que no llegan a la ficha pública

    Correo Auth, hashes, claves secretas, propietario interno, razones de moderación y eventos administrativos. La clave pública de Supabase puede estar en React; la clave privilegiada no.

    SIGUIENTE ETAPA

    Pasar de propuesta a implementación

    1. Crear Supabase de desarrollo y revisar schema.sql.
    2. Implementar las RPC de guardado/publicación y administración. Probar accesos permitidos y denegados.
    3. Configurar Auth, confirmación, recuperación y redirecciones del dominio Cloudflare.
    4. Implementar carga y entrega privada de medios con compensación de errores.
    5. Integrar cliente Supabase y modelos tipados en React; retirar llamadas a /api.
    6. Migrar únicamente los datos elegidos, sin copiar contraseñas compartidas ni promocionar ejemplos ficticios.
    7. Probar registro → publicación → búsqueda → WhatsApp → pausa en staging.
    8. Desplegar frontend Cloudflare con URL y clave pública de Supabase. Retirar el Worker y SQLite anteriores después del corte validado.

    Configuración de compilación: VITE_SUPABASE_URL y VITE_SUPABASE_PUBLISHABLE_KEY. Los secretos se guardan en Supabase, no en variables VITE_*.

    Esta documentación no ejecuta SQL. No se ha creado ni conectado un proyecto Supabase. El SQL de referencia requiere implementar las mutaciones y probar seguridad antes de producción.
